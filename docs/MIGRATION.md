## 1. 앱 개요

휴대폰으로 한글을 처음 배우는 **성인문해학습자**를 위한 웹앱입니다. 설치 없이 주소로 열 수 있고,
홈 화면에 추가하면 앱처럼 쓰이며, 소리를 한 번 받아 두면 인터넷 없이도 동작합니다.
**집에서 혼자** 쓰는 것이 전제라, 옆에서 알려 줄 사람이 없다고 보고 설계해야 합니다.

> 2026-09 까지의 문서는 "70~80대 어르신용"으로 적혀 있었습니다. 연령 설명으로는 맞지만,
> 설계 기준은 **글을 읽지 못한다**는 점입니다. 글로 된 단추·안내·메뉴는 이 학습자에게
> 보이지 않는 것과 같습니다. (2026-10-23 사용자 정의)

**화면 5개**

| 화면 | 내용 |
|---|---|
| 기초 학습 | 1단계 자음 → 2단계 모음 → 3단계 소리 합치기 → 4단계 받침 읽기 |
| 글씨 쓰기 연습 | 자음·모음 24자의 필순을 움직이는 GIF로 |
| 글자 한눈에 보기 | 자음·모음을 골라 소리로 익히기 |
| 낱말 배우기 | 생활 낱말 761개, 15개 갈래, 쪽 넘김 |
| 낱말 맞히기 놀이 | 그림 보고 낱말 고르기 10문제 |

**교육 설계상 꼭 지켜야 할 것** (그냥 기능이 아니라 이 앱의 존재 이유입니다)

1. **글자 이름과 소리를 구분해 가르친다.** "기역"은 이름, "그"가 소리. 성우가 세 도막으로
   끊어 말한다: ① 이 글자의 이름은, 기역 → ② 소리는, 그 → ③ 예를 들면, 가방.
2. **소리를 합치는 과정을 귀로 들려준다.** 학습자는 글자 발음을 통째로 외우는 경향이 있어,
   「그」+「아」를 한 호흡으로 이어 읽은 녹음을 **3배속**으로 재생해 「가」로 뭉쳐지는 걸
   직접 듣게 한다.
3. **받침은 자음 이름의 끝소리로 읽는다.** 「바」+ 비읍의 끝소리 「읍」 → 「밥」.
   **예외 3개**(ㄱ=윽, ㄷ=읃, ㅅ=읏)는 성우가 "조심하세요!"로 따로 경고한다.
4. **큰 글자, 큰 단추, 존댓말.** 기본 22px(폰 18px), 단추 높이 50px 이상.
5. **말 속도를 늦춘다.** 조각마다 다릅니다. 4절의 표를 보세요. 이것도 설계의 일부입니다.

```
hangul/
├─ index.html                 364.7 KB  앱 전체 (HTML+CSS+JS+데이터 인라인)

├─ manifest.webmanifest         0.7 KB  홈 화면 앱 설정
├─ vercel.json                  0.7 KB  캐시 머리말 설정
```

**index.html 안에 인라인된 데이터**

| 블록 | 크기 | 내용 |
|---|---|---|
| `window.WORDS_DATA` | 9.7 KB | 낱말 761개 (15갈래) · 그림(이모지) 있는 낱말은 250개 |
| `window.STROKE_GIFS` | 243.7 KB | 필순 GIF 24개 (base64) |
| `window.AUDIO` | 31.3 KB | 소리 키 → `audio/aN.mp3` 대응표 |
| `window.AUDIO_BIN` | 6.2 KB | 묶음 색인 (조각별 길이 배열) |

> ⚠️ **중요**: `window.AUDIO` 와 `window.AUDIO_BIN` 은 `index.html` 안에서
> **메인 스크립트보다 뒤에** 삽입됩니다. 따라서 스크립트 로드 시점에 읽으면 비어
> 있습니다. 반드시 **쓸 때마다 새로 읽어야** 합니다. 이걸 놓쳐서 "소리 0개를 받고도
> 완료라고 표시"하는 버그가 났었습니다.

**동작 방식**

- 소리는 `new Audio()` 요소 **하나**를 공유해 재생합니다. 여러 도막을 이어 붙일 때는
  `ended` 이벤트로 다음 도막을 재생하고, 사이에 `setTimeout`으로 쉼을 넣습니다.
- 휴대폰은 화면을 누른 직후가 아니면 소리를 막으므로, **첫 터치 때 무음 WAV를 한 번
  재생**해 오디오를 열어 둡니다(`unlockAudio`). 이게 없으면 시간차 재생이 전부 막힙니다.
- **소리는 `audio/audio.bin` 한 덩어리로 받아 둡니다.** 재생할 때는
  `blob.slice(시작, 끝, 'audio/mpeg')` → `URL.createObjectURL()` 로 필요한 자리만
  잘라 씁니다. 묶음을 아직 받지 않았으면 낱개 주소로 재생합니다.
  (`setSrc()` 하나가 이 갈림길을 담당합니다. 임시 주소는 다음 소리로 넘어갈 때 치웁니다.)
- 서비스 워커: 화면은 **네트워크 우선**(4초 뒤 저장본), 묶음·아이콘은 **저장본 우선**.
  **낱개 mp3 는 저장하지 않습니다** — 예전에 이것들을 하나씩 저장하다가 7-1 문제가
  났습니다. 이미 저장해 둔 것이 있으면 그건 그대로 씁니다.
- 소리 캐시 이름은 `hangul-audio`(판 번호 없음), 화면 캐시는 `hangul-shell-<지문>`입니다.
  지금은 `hangul-shell-311228a4e3`. **`index.html` 을 고치면 반드시
  `python tools/stamp_sw.py` 를 돌려 지문을 새로 찍으세요.** 안 그러면 휴대폰이
  옛 화면을 계속 씁니다.
- 첫 화면 맨 아래에 **판 번호**가 작게 나옵니다(`APP_VERSION`). "고쳤는데 그대로인데요"
  할 때 먼저 볼 곳입니다.

**경로에 의존하지 않습니다.** `sw.js`, `manifest`, 모든 링크가 상대경로라서
`/hangul/` 아래든 도메인 루트든 그대로 동작합니다.

## 4. 소리 파일 다시 만들기

기존 `audio/` 폴더를 그대로 쓰면 재생성할 필요가 없습니다.
**음질·용량을 바꾸거나 낱말·안내문을 추가할 때만** 필요합니다.

**대본은 따로 없습니다.** `index.html` 안의 자료(`JAUM`/`MOUM`/`BATCHIM`/`WORDS_DATA`)가

| -15% | 낱말, 글자 설명 |
| -20% | 한 글자 또렷이 읽기 |
| -25% | 소리를 이어 붙여 읽기 (귀로 합쳐지는 과정을 들려주는 대목) |

### 4-1. edge-tts (지금 쓰는 방식, 무료)

**사용한 음성**: Microsoft Edge TTS 의 `ko-KR-SunHiNeural` (여성, 아나운서풍). 무료이고
API 키가 필요 없습니다. 지금 배포된 소리가 이 방식으로 만들어졌습니다.


> ⚠️ edge-tts 는 **비공식 경로**입니다. 공짜지만 예고 없이 막힐 수 있습니다.
> 경로당·복지관에 배포하는 공공성 있는 서비스라면 4-2 를 검토하세요.

## 7. 알려진 문제

### 7-1. ✅ 저장공간 부족으로 일부 소리가 빠짐 — **2026-09-21 해결**

소리를 1,226개 파일로 따로 저장하던 것이 문제였습니다. 파일당 약 1.25KB의 관리 정보가
붙어 **10.18MB 데이터가 실제로는 12.43MB를 차지**했고, 저장공간이 빠듯한 기기에서
일부만 저장되는데 앱은 그걸 "와이파이 문제"라고 잘못 안내했습니다.

| 기기 할당량 | 저장된 소리 | 실패 원인 |
|---|---|---|
| 6MB | 582 / 1226 | QuotaExceededError 1,932건 |
| 12MB | 1200 / 1226 | QuotaExceededError 78건 |
| 14MB | 1226 / 1226 ✅ | 없음 |

**고친 내용 (네 가지 모두)**

1. `QuotaExceededError` 를 가려내 **"⚠️ 저장공간이 부족합니다. 사진이나 쓰지 않는 앱을
   정리해 주세요"** 로 안내합니다. 더는 와이파이 탓을 하지 않습니다.
2. `navigator.storage.persist()` 로 자리를 잡아 둡니다. "잘 되다가 어느 날 안 되는"
   증상을 막습니다.
3. `navigator.storage.estimate()` 로 **받기 전에** 공간을 봅니다. 모자라면 10MB를
   헛되이 받지 않고 미리 알려 줍니다.
4. 소리 1,226개를 **`audio.bin` 한 덩어리로 묶었습니다.** 원본 mp3를 그대로 이어 붙인
   것이라 음질 손실이 없습니다(1,226개 전부 바이트 단위로 대조해 확인).

| | 이전 | 이후 |
|---|---|---|
| 캐시 항목 수 | 1,226개 | **1개** |
| 실제 차지 용량 | 12.43MB | **10.18MB** |
| 받을 때 요청 | 1,226번 | **1번** (약 2초) |

### 7-2. 아이폰은 사파리와 홈 화면 앱의 저장공간이 다름

사파리에서 소리를 받아도 **홈 화면 앱에는 없습니다.** 그래서 순서가 중요합니다.
① QR로 열기 → ② 홈 화면에 추가 → ③ **앱을 열고 그 안에서** 소리 받기.

(다만 이 안내가 글자뿐입니다 — 11절 ④ 참고)

### Supabase — 이 앱에는 권하지 않습니다

소리 파일을 Supabase Storage에 두는 방안은 **하지 마시길 권합니다.** 다른 도메인이 되어
CORS 설정이 필요하고, 서비스 워커의 캐시 처리가 복잡해지며, 정적 파일 10MB는 Vercel이

localStorage** 로 충분합니다(11절 ⑦). 로그인은 이 학습자에게 큰 장벽입니다.
서버에 올려야 한다면 **기기별 익명 ID** 방식을 권합니다.

## 10. 판 되돌리기

판마다 git 태그가 붙어 있습니다. **`v1.1` 이 2026-09-21 작업 전체(= 버전 1)**이고,
돌아올 수 있는 기준점입니다. 첫 화면 맨 아래에 나오는 번호가 지금 그 휴대폰에 깔린 판입니다.

```bash
git tag -n1                      # 어떤 판들이 있나
git show v1.1                    # 그 판에 무엇이 들어갔나
git switch -c fix-1.1 v1.1       # 1.1 에서 가지 쳐서 작업
```

`main` 을 되돌려야 한다면 **`git reset --hard` 대신 `git revert`** 를 쓰세요.
이미 푸시된 이력을 지우면 Vercel 배포 기록과 어긋납니다.

운영 주소만 급히 이전 판으로 돌리려면, Vercel → 프로젝트 `hangul` → **Deployments**
에서 그 판의 배포를 찾아 **Promote to Production**. 저장소는 그대로 둔 채 주소만
바뀌므로, 원인을 찾는 동안 학습자는 멀쩡한 앱을 쓸 수 있습니다.

**판을 새로 낼 때**는 ① `index.html` 의 `APP_VERSION` 을 올리고 ②
`python tools/stamp_sw.py` 로 캐시 지문을 새로 찍고 ③ 커밋·푸시한 뒤 ④ 태그를 붙입니다.
②를 빠뜨리면 휴대폰이 옛 화면을 계속 써서 판 번호도 옛것으로 보입니다.
